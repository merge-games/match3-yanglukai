# 开心消消乐 · 璐恺版

用杨璐恺的 12 张表情照当消除块的单文件三消小游戏。8×8 棋盘，6 个关卡，拖动或点选相邻头像交换，三连消除、下落补充、连锁加分，玩到后面还有直线块和炸弹块。

**完全离线**：双击 `index.html` 即可运行。没有构建、没有 CDN、没有外部字体、没有音频文件，也不依赖任何第三方库。

## 2. 玩法

### 2.1 基本操作

- **拖动**：按住一个圆形头像，向上下左右拖动超过约 0.38 格，与相邻头像交换。
- **点选**：点一个头像，再点它上下左右的相邻头像，完成交换。
- 只有能形成横向或纵向 **3 连及以上** 的交换才会生效。
- 无效交换会播放回弹/抖动动画，棋盘、分数、步数都不变。

### 2.2 消除、下落、连锁

- 横/竖 3 连及以上消除。
- 消除后同列上方头像下落，顶部补充新头像。
- 补充后如果又形成三连，会自动进入下一轮 **连锁（cascade）**。
- 连锁倍率从 **×1** 开始，每多一轮 +1：
  - 第 1 轮 ×1，第 2 轮 ×2，第 3 轮 ×3……
  - 普通块每个 **20 分 × 当前倍率**。
- 连锁时棋盘上会弹出 `+分数` 与 `×N 连击` 飘字。

### 2.3 特殊块

| 形成方式 | 特殊块 | 效果 | `__state().board` 编码 |
|---|---|---|---|
| 横向 4 连 | 横向直线块（`↔`） | 被消除时清掉整行 | `100 + 钗下标` |
| 纵向 4 连 | 纵向直线块（`↕`） | 被消除时清掉整列 | `120 + 钗下标` |
| 5 连及以上 | 炸弹块（`✹`） | 被消除时清掉周围 3×3 | `200 + 钗下标` |

- 特殊块本身也有普通钗的 type，仍然可以参与三连。
- 被匹配或波及时会递归触发，特殊块之间可以连锁引爆。
- 4 连生成直线块、5 连生成炸弹块时，会优先落在本次交换的落点上。
- 普通块 type 仍然是 `0~11`；测试里看到 `100+` / `120+` / `200+` 就是特殊块标记。

### 2.4 提示、重排与音效

- **提示**：点「提示」高亮一组可行的交换，冷却 **5 秒**，按钮上会显示剩余秒数。
- **自动重排**：开局保证无三连、至少有一步可消；每次结算后如果没有可行操作，会自动重排并提示「无路可走，已自动重排棋盘」。
- **音效**：交换、无效交换、消除、连击、特殊块、过关、失败都由 WebAudio 现场合成；右上角 `♪` 可静音，静音状态会存 localStorage。

### 2.5 过关与星级

- 达到目标分即过关，剩余步数不要求清空。
- 步数用尽且未达目标分则失败。
- 星级只按本关得分计算：

| 星级 | 条件 |
|---|---|
| ★ | 得分 ≥ 目标分 |
| ★★ | 得分 ≥ 目标分 × 1.35 |
| ★★★ | 得分 ≥ 目标分 × 1.70 |

关卡选择页会显示每关最好分数、已获得星数；未解锁关卡显示「通关第 N 关解锁」。

## 5. 技术要点

### 5.1 单文件与零依赖

- 所有 HTML、CSS、JS 都在 `index.html` 内，无 `<script src>`、无 `<link href>`、无 `@import`、无 `fetch`。
- 只用系统字体 `system-ui / -apple-system / PingFang SC / Microsoft YaHei`。
- 所有头像走相对路径 `assets/`，可离线双击运行。

### 5.2 同步结算 + 异步视觉

这是一个刻意为可测试性做的设计：

- `__swap(a,b)` 调用后，交换、匹配、消除、特殊块生成、下落、补充、连锁、计分、胜负判定**全部同步完成**。
- DOM 的滑动、下落、爆点、飘字、按钮冷却属于视觉层，不影响内部状态。
- 因此 `__swap` 返回 `true` 时，立刻 `__state()` 就能看到最新分数、步数、棋盘。
- `__tick(ms)` 推进的是游戏虚拟时钟（动画锁、提示冷却、自动重排延迟），不会等待真实动画。

核心结算函数大致分三层：

1. `findRuns()`：扫描横/竖 3 连。
2. `clearWave()`：处理特殊块生成、特殊块递归引爆、计分、移除、重力下落、顶部补充。
3. `resolveBoard()`：循环调用 `clearWave()` 直到没有三连，形成连锁并记录 `lastResolve`。

### 5.3 特殊块编码

`__state().board` 和 `__setBoard(rows)` 使用同一套整数编码：

```text
0..11        普通块（钗下标）
100..111     横向直线块（100 + type）
120..131     纵向直线块（120 + type）
200..211     炸弹块（200 + type）
```

这样棋盘仍然是一个 8×8 数字矩阵，同时特殊块在 `__state().board` 里可见、可断言。

### 5.4 保证局面可玩

- 开局生成时逐格排除会立即形成三连的 type；生成后检查 `findMove()`，没有可行步就重生成。
- 每次结算后：先判胜负；若未结束且没有可行步，立即重排。
- 重排优先保留现有块和特殊块，随机换位；要求「无三连 + 至少一步可消」。连续失败时兜底重新生成。
- `__setBoard` 是测试专用，刻意**不**自动消除、不自动重排；但它会在虚拟时间 400ms 后允许 `__tick` 触发普通自动重排逻辑（用于测试无路可走场景）。

### 5.5 存档

localStorage 使用题面指定的两个键，值都是 JSON：

```text
match3-yanglukai:best:v1      -> [0,0,0,0,0,0]       // 6 关最好分，数组
match3-yanglukai:progress:v1  -> {"unlocked":1,"stars":[0,0,0,0,0,0]}
```

- `best` 与 `stars` 只增不减：取历史最大值。
- 过关会更新 `best`、`stars`、`unlocked`；失败也会更新 `best`（如果本局分数更高），但不会增加星数或解锁。
- localStorage 不可用（例如某些浏览器的 file:// 限制）时自动退回内存存档，不影响本局游玩，只是刷新后不保留。
- 静音状态额外存在 `match3-yanglukai:muted:v1`，不属于题面要求的进度键。

### 5.6 移动端

- 棋盘 CSS 使用 `touch-action: none`，并监听 `touchmove` 阻止页面滚动。
- 交互用 Pointer Events 统一鼠标/触摸；桌面拖动和点选都可玩。
- 棋盘宽度 `100%`，最大约 457px；页面无横向滚动。
- 在 390×844 的 iframe 窄屏下实测：`innerWidth=390`、`scrollWidth=390`、棋盘 350×350、64 个 tile、无横向溢出。
- `:root` 品牌色 `#9a2130`、背景 `#f6efec` 系、圆角卡片、中文 UI，与现有小游戏风格保持一致。

### 5.7 音效

- 全部由 `AudioContext` + `OscillatorNode` / `BiquadFilterNode` 现场合成。
- 第一次用户手势（点击/拖动）时才初始化或恢复 AudioContext，避免自动播放限制。
- 没有 `.mp3/.wav/.ogg` 文件。

## 6. 自动化测试钩子

所有钩子都在 `window` 上，正常玩法不依赖它们。

### 6.1 必备钩子

#### `window.__state()`

返回：

```js
{
  level,       // 0..5
  score,       // 当前分
  target,      // 当前关目标分
  movesLeft,   // 剩余步数
  phase,       // 'home' | 'select' | 'playing' | 'won' | 'lost'
  types,       // 本关使用的钗种类数（5..8）
  best,        // 本关最好分
  stars,       // 本关历史最好星数 0..3
  board        // 8×8 整数矩阵，特殊块编码见 5.3
}
```

#### `window.__level(i)`

直接进入第 `i` 关（**0 基**，`0` 是第 1 关）。会重置本关分数、步数、棋盘、提示冷却，不要求该关已解锁。非法下标返回 `false`。

#### `window.__setBoard(rows, opts?)`

用 8×8 二维数组重设棋盘：

```js
__setBoard([
  [0,1,2,3,4,5,6,7],
  ...
]);
```

- 普通值 `0~11`，也可直接传 `100+type` / `120+type` / `200+type` 特殊块。
- 只重设棋盘和显式传入的状态，**不会自动消除、不会自动重排**。
- 为保证测试构造稳定，进入后 400ms 虚拟时间内不会触发自动重排；之后再调用 `__tick(≥400)`，如果棋盘无路可走，会走正常自动重排逻辑。
- 可选第二参数（为自动化测试额外提供）：

```js
__setBoard(rows, {
  score: 0,        // 覆盖当前分
  movesLeft: 5,    // 覆盖剩余步数
  target: 800,     // 覆盖目标分
  types: 5         // 覆盖本关钗种类数
});
```

返回 `true` / `false`。非法行数、列数或钗下标返回 `false`，原棋盘保持不变。

示例：

```js
__level(0);
__setBoard([...], { score: 0, movesLeft: 10 });
const ok = __swap({r: 4, c: 4}, {r: 5, c: 4});
```

#### `window.__swap(a, b)`

- `a` / `b` 是 `{r, c}`。
- 同步返回 `true` / `false`。
- `true` 表示形成了消除，交换生效，步数已扣，结算已完成。
- `false` 表示不是合法消除交换，棋盘与分数/步数不变。
- 内部状态立即正确；视觉动画异步播放。
- 非相邻、越界、非 `playing`、步数为 0 时返回 `false`。

#### `window.__findMove()`

返回任意一个能形成消除的相邻交换：

```js
{ a: {r: 0, c: 2}, b: {r: 0, c: 3} }
```

或 `null`。不会修改棋盘。

#### `window.__tick(ms)`

手动推进虚拟时钟 `ms` 毫秒。影响：

- 交换动画锁 `busyUntil`；
- 提示 5 秒冷却；
- `__setBoard` 后的自动重排宽限期；
- 无路可走时的自动重排检查。

返回 `{now, busy, phase}`。核心消除逻辑不依赖它，因为 `__swap` 已经同步结算。

### 6.2 额外钩子

#### `window.__lastResolve()`

返回上一次 `__swap` 的结算明细，便于验证连锁/特殊块：

```js
{
  waves: [
    { combo: 1, points: 60, cleared: [[r,c,type,special], ...], spawns: [...], triggered: [...] },
    { combo: 2, points: 190, ... }
  ],
  maxCombo: 2,
  gained: 250,
  at: 虚拟时间
}
```

### 6.3 测试建议

```js
__level(0);
const s = __state();                 // 8×8、无初始三连
const mv = __findMove();             // 至少一步
__swap(mv.a, mv.b);                  // true，立刻结算
__tick(2000);                        // 清动画锁/冷却
```

### 7.3 随机走法平衡模拟

方法：每关用 `__level(i)` 开局，随后每一步从所有合法交换中**随机**挑一个执行，直到过关或步数耗尽；每关 30 局。这个 bot 不会主动凑四连、不会留特殊块，因此只能作为难度下界参考。

## 8. 已知限制 / 未验证点

1. **真机触摸未实测**：只在 headless Chrome 里用合成 PointerEvent 验证了点击/拖动，并在 390×844 iframe 中验证了布局和 `touch-action:none`。没有在真实 iOS / Android 上跑过手势。
2. **音频听感未人工试听**：WebAudio 合成逻辑和静音开关已跑通，headless 环境没有声卡，未评价音色和音量是否合口味。
3. **随机补充不可复现**：连锁长度和分数受 `Math.random()` 补充影响；同样的 `__setBoard` 局面多次跑，连锁层数和总分可能不同，但「至少二次连锁」的构造局面稳定满足。没有接入可控随机种子。
4. **特殊块交互做了收敛**：只实现直线块、炸弹块及其递归引爆，没有实现「两个特殊块交换直接合成」、彩色块、万能块等更复杂玩法。
5. **重排的兜底**：极端情况下如果保留特殊块随机换位 260 次仍无解，会重新生成普通棋盘（特殊块可能丢失），但一定保证无三连且至少一步可走。
6. **localStorage 跨浏览器差异**：Chrome + file:// + 同 profile 已验证；Firefox/Safari 对 file:// localStorage 的策略可能不同。代码已做异常捕获和内存回退，但其他浏览器的刷新持久化未实测。
7. **截图不是 CDP 截图**：本游戏是 DOM 渲染，没有 canvas 图层；使用 headless DOM 截图并统计像素，未使用 CDP `Page.captureScreenshot`。验证了非空画面和布局，但没有做逐像素视觉回归。
8. **测试辅助参数**：`__setBoard(rows, opts)` 的第二参数、`__lastResolve()` 是为验收额外加的，不在题面强制钩子内，不影响正常玩法。
